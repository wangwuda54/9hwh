# Stage 12 SEO Publishing And Link System Report

## 为什么不一次性发布几十万关键词

官网系统的目标不是把关键词库直接变成海量公开页面。一次性发布几十万关键词会同时放大内容质量、收录效率、站内结构、抓取预算和风险控制问题，也会让后续复盘几乎无法进行。更稳妥的做法是先建立“候选 -> reviewed -> queued -> published”的可控节奏，再根据索引、曝光、点击和转化数据逐步放量。

## 关键词库、Cluster、公开页面的关系

关键词库是内部资产，cluster 是内部组织层，公开页面是最终少量、明确、可维护的承接层。不是每个关键词都对应公开页面，也不是每个 cluster 都立刻扩展成大量文章。公开页面应优先服务于核心服务页、平台页、topic hub 和少量经过 review 的文章。

## 发布节奏建议

- 默认每日上限保持在 `12`。
- `20` 是硬上限，超过必须显式 `--force`。
- 发布计划建议按 30 天窗口滚动生成，先保留候选，再选择性推进。
- review pass 和队列状态都满足时，内容才进入可发布范围。

## 内链规则

- 文章至少需要 `4` 个站内内链。
- 至少包含 `1` 个 platform 或 service。
- 至少包含 `1` 个 topic。
- 至少包含 `1` 个 services 总页或 topics 总页。
- 至少包含 `1` 个 contact。
- 构建出的页面必须输出标准 `<a href="">` 链接，而不是 JS 跳转。
- topic / platform / service 页面会自动聚合对应的已发布文章。

## 外链增长计划

- 自有平台主页、视频简介、社媒置顶内容优先回链到首页、服务页或专题页。
- 行业内容优先围绕准备清单、渠道对比、素材检查表争取自然引用。
- 合作伙伴场景优先布局合作页、访谈页、资源页。
- 明确不做垃圾外链、PBN、批量目录站或多域名同内容互链。

## 排名监控计划

- 本阶段先建立 `rank_tracking_seed.json` 结构。
- 后续阶段再接入 Search Console 或真实监控数据。
- 在没有真实数据前，不伪造 impressions、clicks、avg_position。

## 当前状态确认

- 当前仍未 push。
- 当前仍未部署。
- 当前仍未 published。
- reviewed 内容不会被自动改成 published。

## 下一阶段建议

- 把人工确认通过的文章状态从 `draft_received` 逐步切到 `reviewed`，不要批量推进。
- 优先发布 cluster 清晰、内链完整、topic/service 承接明确的内容。
- 接入真实索引与排名数据后，再决定是否扩大每日发布上限。
