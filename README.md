# 9hwh 官网拯救项目说明

## 1. 项目背景

- 官网域名：9hwh.com。
- 当前站点已运行约半年，有收录但基本没有稳定排名。
- 历史上用 Python 批量生成了大量 service 页面，数量约 18000。
- 当前首页更像 service 链接池，不像正式官网。
- 当前内容包含阶段性关键词、高风险行业词和高风险承诺表达。
- 当前关键词池只是阶段性业务输入，不代表官网长期定位。

## 2. 项目判断

本项目不是普通 SEO 修补，也不是继续围绕 service 页面做小改。

本项目按“大改版 + 治理体系重建”处理，核心是：

- 官网定位重建。
- 主结构重建。
- 内容治理重建。
- 关键词治理重建。
- 旧页面分流治理。
- 索引治理。
- 风险表达治理。
- 执行顺序治理。

## 3. 当前问题摘要

- 首页缺少正式官网的信息架构。
- 首页主要承载 service_xxxx 链接，降低品牌可信度。
- 大量 service 页面模板化，缺少独立价值。
- URL 无业务语义，难以形成长期主题资产。
- 关键词池覆盖过宽，混入高风险行业和高风险承诺。
- 高风险表达可能伤害用户信任、平台合规和搜索质量判断。
- 旧页面已被搜索引擎发现，不能粗暴全删或全跳首页。
- sitemap、robots、noindex、301、410、canonical 尚无清晰治理顺序。

## 4. 项目目标

- 保留 9hwh.com 的域名和已有可用信号。
- 把官网改成长期可信的出海数字增长服务站点。
- 首页、导航、核心服务页保持稳定，不绑定阶段性关键词。
- 建立可变关键词内容层，允许业务和关键词池随时变化。
- 对旧 service 页面按数据分流，不做一刀切处理。
- 清除或隔离高风险表达，避免进入主结构。
- 建立个人团队也能执行的轻量治理流程。

## 5. 大改版原则

- 先写规范，再做盘点。
- 先冻结旧页，再分流处理。
- 先重建主结构，再扩展内容中心。
- 先处理高风险表达，再追求收录增长。
- 先做小批验证，再扩大索引治理。
- 重大变化必须记录，低风险小修可在阶段验收时汇总记录。
- 所有不可逆动作必须有证据和回滚点。

## 6. 双层结构原则

新官网必须采用“双层结构”。

长期可信官网层包括：

- 首页、关于我们、核心服务页、服务流程页。
- 合规与服务边界页、案例或能力说明页、联系页。

可变关键词内容层包括：

- 内容中心、国家指南、平台指南、行业观察、FAQ、专题页。

官网层稳定，内容层可变；关键词池只能影响内容层，不能污染主结构。

## 7. 阶段顺序

- 阶段 0：项目规范初始化。
- 阶段 1：现状盘点。
- 阶段 2：官网定位与信息架构。
- 阶段 3：新首页与核心页面设计。
- 阶段 4：关键词池治理体系。
- 阶段 5：旧 service 页面分流策略。
- 阶段 6：索引治理策略。
- 阶段 7：内容中心与长期更新机制。
- 阶段 8：上线检查与观察机制。

## 8. 当前只做阶段 0

当前阶段只完成规范文件，不做以下动作：

- 不改首页代码。
- 不生成首页代码。
- 不生成 sitemap、robots、noindex、301、410 规则。
- 不处理 service 页面。
- 不批量生成新页面。

## 9. 变更要求

后续重大变化必须先更新相关规范文件。

包括：

- 业务方向变化。
- 关键词池变化。
- 首页定位变化。
- 核心服务变化。
- 旧 service 页面处理策略变化。
- 索引策略变化。
- 风险表达规则变化。

未进入相关规范的重大变化，不得进入执行。

## 10. 主要规范文件

- AGENTS.md：AI 助手和协作者总规则。
- project-rules.md：项目硬规则。
- project-status.md：当前阶段、当前限制和当前输出范围。
- stage-gates.md：阶段准入、退出和禁止跨阶段执行规则。
- keyword-policy.md：关键词治理规则。
- site-positioning.md：官网长期定位。
- rebuild-roadmap.md：大改版路线图。
- old-service-policy.md：旧 service 页面治理规则。
- inventory-schema.md：旧 service 页面盘点、分流、批次和回滚字段规范。
- indexing-policy.md：索引治理规则。
- content-policy.md：内容治理规则。
- change-log.md：项目变更记录。
